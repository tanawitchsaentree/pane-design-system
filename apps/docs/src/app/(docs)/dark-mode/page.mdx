# Dark mode

Dial's dark theme is a `data-theme="dark"` attribute switch — the exact mechanism this docs
site's own theme toggle (bottom of the left sidebar on every page) uses, and the same one
`apps/storybook/.storybook/preview.ts`'s toolbar switcher uses.

## Two independent switches, one mechanism

| Switch | Component | What it toggles |
|---|---|---|
| Docs site theme | `DialThemeToggle` (`src/components/DialThemeToggle.tsx`) | `data-theme="dark"` on `<html>`, synced from `next-themes` via `DialThemeSync` |
| Storybook theme | `apps/storybook/.storybook/preview.ts`'s toolbar switcher | The same `data-theme` attribute, independently, inside Storybook's own iframe |

Both switches exist because this docs site and Storybook are two separate Next.js/Vite apps —
neither shares a JS runtime with the other — but both ultimately flip the exact same CSS attribute
`dial-tokens/css/dark` is scoped under, so a component looks identical in both places once dark
mode is on.

## How it works

`dial-tokens/css` (light) is unconditional — it sets every `--ds-*` variable at `:root` with no
attribute required. `dial-tokens/css/dark` defines the same variable names again, but scoped
under a `[data-theme="dark"]` attribute selector, so importing it does nothing until that
attribute is present:

```tsx
import 'dial-tokens/css';
import 'dial-tokens/css/dark';
```

```ts
// Switch to dark:
document.documentElement.setAttribute('data-theme', 'dark');
// Switch back to light:
document.documentElement.removeAttribute('data-theme');
```

Because every component consumes the same `--ds-*` variable names regardless of theme, no
component code branches on the current theme — the same rendered markup simply resolves different
CSS variable values once the attribute changes. This docs site's own `DialThemeToggle` does exactly
this (via `next-themes`, which persists the choice to `localStorage` so it survives a reload).

## High-contrast light

A third theme, `light-contrast-more`, is gated behind
`[data-theme="light"][data-contrast="more"]`. `dial-tokens/css` (the base light import) also
includes an automatic `@media (prefers-contrast: more)` block, so OS-level high-contrast
preference is honored without setting any attribute at all — the explicit `data-contrast="more"`
attribute is only needed for an in-app toggle independent of the OS setting.

## See it in action

Every color swatch on the [Colors](/foundations/colors) foundation page, and every live demo on
every component page, resolves its real value from whichever theme is currently active — switch
the toggle in this page's own header and watch them change.
