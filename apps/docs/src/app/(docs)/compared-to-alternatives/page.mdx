## What makes Dial itself

Every row below is a real, locked decision from `system/DECISIONS.md` — not a claim about any
other system. Rendered as a table (rather than the same content as prose) specifically so this
page has a real non-prose structure, per this docs site's own density rules for overview pages.

| Axis | Dial's locked decision | Source |
|---|---|---|
| Accent usage | A single scarce accent color, reserved for the one most important interactive element in a given view — never used to decorate or emphasize plain text or multiple competing actions at once. | D-001 |
| Visual lineage | Braun-derived: warm-neutral surfaces (not cool gray), no decorative drop-shadows outside layers that genuinely float (modal, popover, toast), hierarchy built from position/weight rather than a tall type scale. | D-001 |
| Type scale | Flat — 1.2 (Minor Third) ratio, deliberately the flattest standard step, one font family for both heading and body. | D-005 |
| Interaction model | Web-first — hover treated as a first-class interaction (not a progressive enhancement), 40px minimum hit-area floor for mouse/trackpad rather than a 44px touch-target mandate, desktop/laptop viewport (1024px) as the first locked breakpoint. | D-002 |
| Behavior source | Borrowed, never hand-rolled — anything with real keyboard/focus/overlay complexity (Dialog, Popover, Listbox, etc.) is built on Radix UI or React Aria; Dial's own code is the token-driven visual layer on top. | — |
| CSS direction | Logical properties throughout (`padding-inline-start`, never `padding-left`) from the first line of the system, so RTL support doesn't require a later rewrite. | — |
| Token architecture | Three-tier — primitive → semantic → component, enforced as a lint rule; component code can never reference a primitive token or a raw hex/px value directly. | See [Theming](/theming) |
