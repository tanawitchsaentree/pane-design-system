# Alert

Alert is a persistent, in-flow feedback banner — a message block that stays part of the page
layout until the page/data changes or the user dismisses it.

```tsx
import { Alert } from 'dial-react';
```

## Usage

Alert is a persistent, in-flow feedback banner — a message block that stays part of the page
layout until the page/data changes or the user dismisses it (contrast with Toast/Snackbar, which
float above the page and auto-dismiss). Use it for form-level validation summaries, page-level
warnings/errors, or any "something the user needs to notice right now, in context" message that
shouldn't disappear on its own. Render it directly in the document flow (it is not portaled and
has no z-index of its own).

## Rigor Tier: T2

Alert is interactive only in the trivial sense that its optional dismiss control is a native
`<button>` (via `IconButton`) — it has no focus trap, no roving tabindex, and no overlay/portal to
prove via Playwright conformance spec/Gate Proof mutation. Per T2, this component ships: a unit
test suite (interaction + axe, `Alert.test.tsx`), the contrast self-check below, and the
hit-area/non-color-cue self-check below — no conformance spec, no Gate Proof mutation.

## Accessibility

- **Keyboard:** The dismiss button (when `dismissible`) is a plain native `<button>` — reachable
  via Tab, activatable via Enter/Space, exactly like every other `IconButton` in the system. No
  custom keyboard handling is implemented (or needed).
- **Screen reader:** Root renders `role="alert"`, which per the ARIA spec implies
  `aria-live="assertive"` + `aria-atomic="true"` — assistive tech announces the whole message as
  soon as it mounts. This is a stronger interruption than Toast's own live-region treatment,
  matching Alert's "needs attention now" positioning versus Toast's less-interruptive one. The
  dismiss button always has an accessible name via `dismissLabel`/`aria-label` (default
  `'Dismiss alert'`) since it carries no visible text.
- **Focus:** Alert never moves focus on mount (non-modal, unlike Dialog) and the dismiss button
  doesn't trap focus — verified indirectly since `Alert.test.tsx` interacts with the dismiss
  button via `userEvent.click` with no focus-trap assertions required.
- **Icon semantics:** The default icon (and any custom `icon` override) is rendered
  `aria-hidden="true"` — the adjacent `title`/description text already carries the meaning, and
  the icon is reinforcement, matching `Icon.tsx`'s own "decorative unless it needs an accessible
  name" contract. **UNVERIFIED:** whether a screen reader's rendering of `role="alert"` differs
  meaningfully across browsers/AT combinations for a long description — this is real-AT behavior
  that jsdom cannot exercise; not something this unit-test suite can prove.

### Hit-area self-check

The dismiss button is a plain `IconButton size="sm"`, which resolves to `size.control.sm` = 40px
(D-004) — meets the locked web-first minimum (40px, D-002) for a mouse/trackpad target. No other
element in Alert is interactive.

### Non-color cue self-check

Every variant renders a **different icon silhouette**, not a recolored copy of the same shape,
verified by imagining the screen in grayscale/forced-colors:

- `default` — circle outline with a dot-and-stem (i-style) mark
- `success` — circle outline with a checkmark
- `warning` — triangle outline with an exclamation mark
- `danger` — octagon outline with an X
- `info` — square (rounded-corner) outline with a dot-and-stem (i-style) mark

`default` and `info` share the same interior glyph (dot-and-stem) but differ in outer silhouette
(circle vs. square) — still distinguishable by shape alone. Additionally, the
`border-inline-start` accent bar is rendered at `border-width.thick` (2px) versus the other three
sides' `border-width.hairline` (1px) — a width/position difference, not just a color difference,
so the "this side is the accent" cue survives grayscale too.

### Contrast self-check

WCAG, computed from resolved hex in `packages/tokens/build/css/{light,dark}.css`, relative-
luminance formula, both themes:

| Pairing | Light | Dark | Minimum | Result |
|---|---|---|---|---|
| `content.bodyText` (text.default, description) on any variant's `bg` | 11.11–12.39:1 | 11.11–12.39:1 | 4.5:1 (text) | PASS (huge margin) |
| `variant.*.titleText` (role.*.subtleText) on own `bg` — success | 5.68:1 | 8.99:1 | 4.5:1 (text) | PASS |
| `variant.*.titleText` on own `bg` — warning | 8.40:1 | 9.11:1 | 4.5:1 (text) | PASS |
| `variant.*.titleText` on own `bg` — danger | 6.01:1 | 9.10:1 | 4.5:1 (text) | PASS |
| `variant.*.titleText` on own `bg` — info | 5.74:1 | 9.06:1 | 4.5:1 (text) | PASS |
| `variant.*.titleText` on own `bg` — default (neutral) | 7.63:1 | 8.46:1 | 4.5:1 (text) | PASS |
| `variant.*.accent` (icon glyph tone, non-text UI) on own `bg` — success | 3.85:1 | 5.46:1 | 3:1 (UI) | PASS |
| `variant.*.accent` on own `bg` — warning | 5.87:1 | 5.40:1 | 3:1 (UI) | PASS |
| `variant.*.accent` on own `bg` — danger | 4.12:1 | 5.33:1 | 3:1 (UI) | PASS |
| `variant.*.accent` on own `bg` — info | 3.89:1 | 5.45:1 | 3:1 (UI) | PASS |
| `variant.default.accent` (`color.border.interactive`) on own `bg` (neutral) | 3.47:1 | **2.99:1** | 3:1 (UI) | **EXCEPTION (inherits E-001 scope)** |

**Exception detail (inherits E-001/D-019/D-021, not a new exception):** the `default` variant's
accent bar reuses `color.border.interactive` — the exact same token Toast's own `default` variant
accent already uses, which was already accepted at an equivalent shortfall (2.99:1 vs
`surface.overlay` in dark) under E-001. Here the shortfall is against `role.neutral.subtleBg`
instead, same token, same ~0.5%-under-3:1 margin, same decorative (non-boundary) role. Scope stays
exactly as narrow as E-001: the accent bar does not define Alert's panel edge (that's
`content.border` = `color.border.hairline`, itself already an accepted sub-3:1 decorative divider
per D-014/D-019 precedent) and is not the only cue distinguishing the `default` variant — the
icon glyph (circle + dot/stem) and title/description copy carry the actual meaning. Not usable as
precedent beyond this narrow decorative-accent case; `success`/`warning`/`danger`/`info` all clear
3:1 without needing this exception.

## Related

- **Toast/Snackbar** — transient, portaled, auto-dismissing notifications; use those instead of
  Alert for messages that shouldn't persist in the page layout.
- **Badge** — a much smaller, single-line informational label with no title/description/dismiss
  slots; Alert's tinted-panel color treatment is Badge's `subtle` recipe scaled up to block level
  (same `role.*.subtleBg`/`subtleText` tokens).
- **Dialog** — for feedback that must block the page and require an explicit decision, unlike
  Alert's non-modal `role="alert"` announcement.
