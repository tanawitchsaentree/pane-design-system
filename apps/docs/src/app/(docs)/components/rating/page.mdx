# Rating

Rating renders a row of `max` native `<input type="radio">` elements sharing one `name`,
visually replaced by star icons.

```tsx
import { Rating } from 'dial-react';
```

## Demo

<Demo code={`<Rating name="product-rating" aria-label="Rate this product" value={value} onChange={setValue} />`}>
  <BasicRating />
</Demo>

## Usage

Rating renders a row of `max` native `<input type="radio">` elements sharing one `name`, visually
replaced by star icons — the same native-radio-group technique `Radio`/`RadioCards` use, just with
a repeated star glyph instead of a dot or a card. Use it for a discrete 1-`max` whole-star rating
(e.g. picking a review score, or displaying an average).

## Variants

Rating has no visual `variant` prop. Its two prop-driven states/shapes:

`readOnly` displays a value without letting it change, while keeping every star focusable — the
right choice for showing an average rating left by other people.

<Demo code={`<Rating name="average-rating" aria-label="Average rating" value={4} readOnly />`}>
  <RatingReadOnly />
</Demo>

`disabled` removes every star from the tab order entirely, via the native `disabled` attribute on
each radio — the right choice when the whole control isn't relevant yet (e.g. a step in a form the
user hasn't reached).

<Demo code={`<Rating name="disabled-rating" aria-label="Rate this product" defaultValue={2} disabled />`}>
  <RatingDisabled />
</Demo>

`max` controls how many stars are rendered — the count is a plain integer, not an enum, so any
whole number works.

<Demo code={`<Rating name="ten-star-rating" aria-label="Rate out of 10" max={10} defaultValue={7} />`}>
  <RatingMax />
</Demo>

Rating supports the same controlled (`value`/`onChange`)/uncontrolled (`defaultValue`) duality as
every other form control in this system. This composition shows both side by side: the controlled
instance's value lives in the parent's own state (and is echoed above it), while the uncontrolled
instance's value lives entirely in the DOM.

<Demo code={`<Rating name="controlled-demo" aria-label="Controlled rating" value={value} onChange={setValue} />
<Rating name="uncontrolled-demo" aria-label="Uncontrolled rating" defaultValue={3} />`}>
  <RatingControlledVsUncontrolled />
</Demo>

## Accessibility

- **Keyboard:** arrow keys cycle selection between stars sharing the group's `name` — 100% native
  radio-group behavior, not implemented by this component. `readOnly` blocks this by calling
  `preventDefault()` in `onKeyDown` for Space/arrow/Home/End (and in `onClick` for pointer input) —
  **not covered by an automated jsdom test** (jsdom doesn't fully model native radio-group
  arrow-key selection, same honest limit `Radio.tsx` documents); proven instead in
  `packages/conformance/specs/w5-rating.spec.ts` running in a real browser.
- **Screen reader:** each star's own `aria-label` is `"{n} star(s) of {max}"`, set automatically —
  not left to the caller to wire up per star.
- **Non-color cue:** selected vs. unselected stars are a real shape swap — an outline-path `<svg>`
  and a filled-path `<svg>` sit as siblings inside each star, and exactly one is `display:block` at
  a time via `data-state`. This is deliberately not a single recolored glyph: under forced-colors
  mode, where `rating.star.selected`/`unselected`'s color tokens collapse to the same system color,
  the two stars remain structurally distinguishable by shape.
- **Hover preview:** hovering a star highlights it and every star before it, before the value
  commits. Implemented with plain React state (`onMouseEnter`/`onMouseLeave`) rather than the
  common CSS `:hover ~` sibling-selector shortcut — that shortcut typically pairs DOM order with
  *visual* order (via `flex-direction: row-reverse`) to make later-DOM-siblings highlight earlier
  ones while still reading left-to-right, which breaks under `dir="rtl"` (where "visually before"
  and "earlier in DOM order" stop matching). The state-driven version compares plain integer
  indices and never reasons about physical direction, so it needs no RTL-specific handling.
- **Focus:** each star's hit area (the `label` wrapping the hidden input) is ≥40px
  (`size.control.sm`), regardless of how much smaller the visible star glyph is (`size.icon.lg`,
  centered via flex) — same pattern as Radio/Checkbox/Switch.
