# Button

Native `<button>`-based interactive control for triggering actions — form submits, dialog opens,
any click-driven action. Four fill treatments, three intents (with `primary` reserved for the
single most important action per view, per D-001 accent scarcity), a loading state, and optional
leading/trailing icon slots.

```tsx
import { Button } from 'dial-react';
```

## Disabled

`disabled` removes the button from the tab order via the native `disabled` attribute, independent
of `loading` (which also disables, but additionally shows a spinner and `aria-busy`).

## Keyboard interaction

No keyboard behavior beyond native Tab focus and Enter/Space activation — standard `<button>`
semantics, nothing custom.

## Accessibility

**Keyboard:** Native `<button>` semantics — Tab/Shift+Tab to move focus, Enter or Space to
activate. Disabled (including while `loading`) removes it from the tab order via the native
`disabled` attribute.

**Screen reader:** While `loading`, the button is `disabled` and `aria-busy="true"`, and the
visible Spinner exposes `role="status"` so the pending state is announced. Icon slots
(`leftIcon`/`rightIcon`) are wrapped with `aria-hidden="true"` since the visible label is the
accessible name.

**Focus:** `:focus-visible` uses the dedicated focus-ring token (color/width/offset) — never a
shadow ring, per braun-flat rule 4. Outline variant's border color uses `color.border.interactive`
(D-014) to meet the 3:1 UI-boundary contrast minimum.

## Related

- **IconButton** — the icon-only variant of Button, extending its variant/intent/size/loading API 1:1.
- **Link** — the non-button interactive text element; use when the action is navigation styled as
  inline text rather than a control.
- **Spinner** — rendered inside Button automatically when `loading` is true.
