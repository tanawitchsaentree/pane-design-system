# RadioCards

RadioCards is a "choose 1 of N" control where the whole card — not just a small dot — is the
click target (e.g. picking a plan/tier).

```tsx
import { RadioCards } from 'dial-react';
```

## Usage

RadioCards is a "choose 1 of N" control where the whole card — not just a small dot — is the
click target (e.g. picking a plan/tier). It's backed by nothing but a native
`<input type="radio">` group sharing one `name`, exactly the same primitive `Radio` uses, just
with a much bigger, fully-clickable visual on top. Declare cards as `RadioCards.Item` children of
a `RadioCards` root.

Note on public surface: this component's source sets two real `displayName`s — `RadioCards.Item`
(the per-card sub-part, meant to be used, but only as a child of the root — it throws if rendered
outside one) and `RadioCards` itself, the public root export that `RadioCards.Item` is attached
to as a static property (`RadioCards.Item = RadioCardsItem`). Import `RadioCards` and use
`RadioCards.Item` as its compound sub-part, exactly as shown above — `RadioCards.Item` is not an
internal-only implementation detail, it's the documented way to declare each card.

## Do and Don't

<DoDont
  dos={[
    "Give RadioCards a name — it's the entire mechanism that groups every RadioCards.Item's underlying radio input for the browser's native roving focus/Arrow-key cycling.",
    "Use value/onChange for controlled usage, defaultValue for uncontrolled — both are plain strings, matching every other Standalone control in the system.",
    "Write any content you like inside RadioCards.Item (title, description, icon) — every bit of text becomes that card's accessible name for free via the native label-wraps-input algorithm. No extra aria-label needed on the item.",
    "Pass aria-label/aria-labelledby on the RadioCards root — a radio group needs its own accessible name (dev-time console warning fires if you forget, mirroring Listbox's own check).",
    "Disable a single card via RadioCards.Item's own disabled, or the whole group via the root's disabled — both compose (a card disabled at the group level stays disabled even if its own disabled is false).",
  ]}
  donts={[
    "Don't expect arrow-key cycling or roving tabindex to be covered by RadioCards.test.tsx (jsdom) — it's native browser behavior, proven only in packages/conformance/specs/w5-radiocards.spec.ts (real browser). See the Accessibility note.",

## Variants

<Demo code={`<RadioCards name="tier-vertical" aria-label="Choose a tier" orientation="vertical" defaultValue="pro">
  <RadioCards.Item value="starter">Starter</RadioCards.Item>
  <RadioCards.Item value="pro">Pro</RadioCards.Item>

  <RadioCardsVertical />

`orientation` (`'horizontal'` default, or `'vertical'`) is the only visual variant.

Setting the group's own `disabled` disables every card at once — each card's underlying radio
input picks up `disabled`, so none of them are focusable or clickable.

<Demo code={`<RadioCards name="plan-disabled" aria-label="Choose a plan" disabled defaultValue="starter">
  <RadioCards.Item value="starter">Starter — $9/mo</RadioCards.Item>
  <RadioCards.Item value="pro">Pro — $29/mo</RadioCards.Item>
  <RadioCards.Item value="enterprise">Enterprise — Contact us</RadioCards.Item>
</RadioCards>`}>
  <DisabledRadioCards />
</Demo>

`required` sets `aria-required` on the `radiogroup` so assistive tech announces that a choice is
mandatory — RadioCards renders no visual difference of its own for this state; pair it with a
label or helper text (e.g. via `FormField`) that says so.

<Demo code={`<RadioCards name="plan-required" aria-label="Choose a plan" required>
  <RadioCards.Item value="starter">Starter — $9/mo</RadioCards.Item>
  <RadioCards.Item value="pro">Pro — $29/mo</RadioCards.Item>
  <RadioCards.Item value="enterprise">Enterprise — Contact us</RadioCards.Item>
</RadioCards>`}>
  <RequiredRadioCards />
</Demo>

`invalid` sets `aria-invalid` on the `radiogroup` (e.g. "you must choose one" after a failed
submit). Like `required`, it's a semantic flag for assistive tech — the visible error message
still needs to come from a sibling like `HelperText`.

<Demo code={`<RadioCards name="plan-invalid" aria-label="Choose a plan" invalid>
  <RadioCards.Item value="starter">Starter — $9/mo</RadioCards.Item>
  <RadioCards.Item value="pro">Pro — $29/mo</RadioCards.Item>
  <RadioCards.Item value="enterprise">Enterprise — Contact us</RadioCards.Item>
</RadioCards>`}>

## Composition

RadioCards nested inside `FormField` needs no `aria-label` of its own — `FormField` clones
`aria-labelledby` (pointing at its own label text) onto the group automatically, the same wiring it
gives every other control it wraps.

<Demo code={`<FormField label="Choose a plan" required helperText="You can change this later in billing settings.">
  <RadioCards name="plan-form-field">
    <RadioCards.Item value="starter">Starter — $9/mo</RadioCards.Item>
    <RadioCards.Item value="pro">Pro — $29/mo</RadioCards.Item>
    <RadioCards.Item value="enterprise">Enterprise — Contact us</RadioCards.Item>
  </RadioCards>
</FormField>`}>
  <RadioCardsInFormField />
</Demo>

A more realistic composition: two independently-controlled RadioCards groups (plan and billing
cycle) inside one real `<form>`, each wrapped in its own `FormField`, submitted together with a
`Button`.

<Demo code={`<form onSubmit={(e) => e.preventDefault()}>
  <FormField label="Plan">

      <RadioCards.Item value="starter">Starter — $9/mo</RadioCards.Item>

### `RadioCards.Item`

`RadioCardsItem` is a module-private `const` in `RadioCards.tsx` — attached to the public
`RadioCards` export as a static property (`RadioCards.Item = RadioCardsItem`) rather than exported

| Prop | Type | Default | Description |
|---|---|---|---|
| `value` | `string` | — (required) | This card's value. |
| `disabled` | `boolean` | `false` | Disables just this card (OR'd with the group's `disabled`). |
| `children` | `ReactNode` | — | Card content — becomes the radio's accessible name. |

## Accessibility

- **Keyboard:** Tab moves focus onto/off the whole group (the browser lands on the checked card,
  or the first card if none is checked yet — native radio-group behavior). Arrow keys cycle
  selection between cards sharing the group's `name`; this and the resulting roving tabindex are
  100% native browser behavior, not code this component implements — same honest limit `Radio.tsx`
  documents. **Not covered by an automated jsdom test**; verified in a real browser via
  `packages/conformance/specs/w5-radiocards.spec.ts`, which asserts `document.activeElement`/
  `.checked` directly rather than importing `_roving-focus.ts`'s helpers (those were written
  against React Aria's `useSelectableCollection`, which sets a `tabindex` DOM attribute per item —
  native radio groups never do, so pointing those helpers at RadioCards would silently pass without
  proving anything).
- **Screen reader:** each card's accessible name comes from its own content via the native
  label-wraps-input algorithm — a card with a title and description needs no extra wiring. The
  group itself needs its own `aria-label`/`aria-labelledby` (see Do).
- **Non-color cue:** the selected card's border thickens (not just changes color) and a checkmark
  glyph appears in the corner indicator — two independent non-color signals, so selection state
  survives forced-colors mode where the border/background color tokens collapse.
- **Focus:** the whole card (the `label` wrapping the hidden input) is the hit area and carries
  the focus ring, not just the small corner indicator — verified ≥40px in
  `w5-radiocards.spec.ts` (cards are typically larger than this floor already, but the floor is
  enforced, not assumed).

## Related

- **Radio** — the underlying native-input technique RadioCards extends with a bigger,
  fully-clickable visual; no new behavior, only a new visual layer.
- **Fieldset** — provides `<legend>`/group semantics for a plain `Radio` group; RadioCards doesn't
  use it because its visual is a row/column of standalone cards, not a bordered fieldset box — its
  accessible name comes from the root's own `aria-label`/`aria-labelledby` instead.
- **Listbox** — the Collection-family analog for "choose 1 (or more) from a list," but built on a
  different engine (React Aria) and a different prop vocabulary (`selectedKeys`) because it models
  a keyed collection, not a single value.
