# InputGroup

InputGroup composes a control (typically an `Input` or a raw `<input>`) with prefix/suffix
adornments into one visually unified bordered group, built on `Flex` from the layout wave. It's
the right choice when the adornment is a multi-character block that should read as its own
contiguous segment (e.g. "$" + amount + "USD") — as opposed to `Input`'s own
`leftElement`/`rightElement`, which are small in-box icon glyphs sharing the same bordered box as
the text.

```tsx
import { InputGroup } from 'dial-react';
```

Because InputGroup is built directly on `Flex`, it inherits `Flex`'s own `wrap` and `justify`
props — useful when the group needs to reflow at a narrow width, or when the control itself
shouldn't stretch to fill the available space.

## Accessibility

**Keyboard:** None of its own — keyboard behavior belongs entirely to the composed control (e.g.
the native `<input>` inside it).

**Screen reader:** InputGroup introduces no new role — it's purely a layout/visual composition.
Both `prefix` and `suffix` are rendered with `aria-hidden="true"` (verified in
`InputGroup.test.tsx`), so any adornment that conveys real meaning needs its own accessible
pairing via `Label`/`HelperText`, not the adornment text alone.

**Focus:** Focus passes straight through to the inner control; the group wrapper itself is not a
focus target and does not add a focus ring of its own.

## Related

- `Input` — the typical control composed inside InputGroup; use Input's own
  `leftElement`/`rightElement` instead for small in-box icon adornments.
- `Flex` — the layout primitive InputGroup is built on (Reuse Check: no bespoke flexbox
  implementation).
- `FormField` — pairs a Label/HelperText around an InputGroup's control when the prefix/suffix
  conveys meaning that needs an accessible equivalent.
