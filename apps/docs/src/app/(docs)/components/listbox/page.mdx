# Listbox

Listbox renders an ARIA `listbox` (`role="listbox"` + `role="option"` children) with real
keyboard navigation, typeahead, and roving tabindex — all borrowed from React Aria, not
hand-written.

```tsx
import { Listbox } from 'dial-react';
```

## Usage

Listbox renders an ARIA `listbox` (`role="listbox"` + `role="option"` children) with real
keyboard navigation, typeahead, and roving tabindex — all borrowed from React Aria
(`@react-stately/list`'s `useListState` + `@react-aria/listbox`'s
`useListBox`/`useOption`/`useListBoxSection`), not hand-written. It is the template component for
Wave 5 (Selection): Select, Combobox, MultiSelect, RadioCards, and TagInput all reuse this same
collection/behavior pattern and its `selectedKeys`/`defaultSelectedKeys`/`onSelectionChange`/
`disabledKeys` vocabulary (D-024's API Vocabulary Contract). Declare options as `Listbox.Item`
children and, optionally, group them under `Listbox.Section` (React Aria's Collection API — these
render nothing themselves; `useListState` walks them to build the actual option collection).

## Composition

A common real usage of `selectionMode="multiple"`: several options actually selected at once (not
just one disabled option, as in the Variants example above), with the caller reading
`selectedKeys` back out to render a live count of how many are chosen.

<Demo code={`<Listbox aria-label="Countries to visit" selectionMode="multiple" selectedKeys={selectedKeys} onSelectionChange={setSelectedKeys}>
  <Listbox.Item key="th">Thailand</Listbox.Item>
  <Listbox.Item key="jp">Japan</Listbox.Item>
  <Listbox.Item key="us">United States</Listbox.Item>
  <Listbox.Item key="de">Germany</Listbox.Item>
</Listbox>
<div>{selectedKeys.size} selected</div>`}>
  <ListboxMultiSelectSummary />
</Demo>

## Accessibility

- **Keyboard:** Arrow Up/Down move the active option and do **not** wrap (React Aria's
  `useSelectableCollection` defaults `shouldFocusWrap` to `false` — verified by reading the
  actually-resolved `@react-aria/selection` source in this repo's lockfile, not just the docs).
  Home/End jump to the first/last option. Typing a character jumps to the next option whose label
  starts with it (React Aria's built-in typeahead). `Mod+A` (Cmd/Ctrl+A) selects every option when
  `selectionMode="multiple"` (confirmed firing in a real browser). Before any option has ever been
  focused, the listbox root itself is `tabindex="0"` and every option is `tabindex="-1"` (ARIA
  Authoring Practices' documented roving-tabindex bootstrap state); the moment an option is
  focused, tabindex moves onto it and stays there. Tab/Shift+Tab move focus out of the whole
  widget in one step and — proven via a round-trip assertion after a real compound-invariant
  investigation, not assumed — correctly remember which option was last active when focus returns.
- **Scroll-into-view:** when the root has a fixed `max-block-size` and overflows, focusing an
  off-screen option scrolls it into view automatically — but only when the focus change's
  *modality* is `'keyboard'` (confirmed by direct testing: a raw `element.focus()` call does not
  scroll; pressing an actual arrow/Home/End key does).
- **Screen reader:** each option carries `role="option"` + `aria-selected` synced to real
  selection state (not a CSS class); the root carries `aria-multiselectable="true"` automatically
  when `selectionMode="multiple"`. A `Listbox.Section` renders as `role="presentation"` (ARIA
  disallows a heading as a direct listbox child) wrapping a hidden heading and a `role="group"`
  with `aria-labelledby` pointing at that heading — the heading is a *visual* label only; the
  group's actual accessible name comes through `aria-labelledby`.
- **FormField integration:** a Listbox nested directly inside `FormField` needs neither
  `aria-label` nor `aria-labelledby` — `FormField` clones its child with `aria-labelledby`
  pointing at its own generated label id (the same wiring `Input`/`Textarea`/`Checkbox` get via
  `htmlFor`/`id`, extended because `<ul role=listbox>` is not a labelable HTML element and gets no
  accessible name from `htmlFor` alone). Verified in
  `packages/conformance/specs/w5-listbox.spec.ts`'s `FormField integration` test that the
  accessible name resolves exactly once, not twice.
- **Focus:** focus-visible renders as an inset outline ring on the option itself, not a shadow.
  Each option's hit area is `size.control.sm` (40px, D-002 web-first minimum) via
  `min-block-size`, regardless of how little text it contains.
- Real-browser-only behavior (Arrow-key roving tabindex, Home/End, typeahead, scroll-into-view,
  Tab-out round-trip — none of which jsdom can prove) is verified in
  `packages/conformance/specs/w5-listbox.spec.ts` across chromium/forced-colors/reduced-motion,
  not in `Listbox.test.tsx`.

## Related

- **FormField** — wires `aria-labelledby` automatically when a Listbox is its child; see
  Accessibility note above.
- **Popover** — the W5 sibling `Select` will place a `Listbox` inside a `Popover.Content` to build
  a dropdown; `Listbox` itself has no floating-panel behavior.
- **Radio/Checkbox/Switch** — other selection controls in the system, but single native-input
  controls with browser-native roving focus, not a multi-item collection with programmatic
  behavior like Listbox. These use the Standalone Control vocabulary (`checked`/`onChange`), not
  Listbox's Collection vocabulary (D-024).
