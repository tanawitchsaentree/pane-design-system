# FormField

FormField is the compound composition of `Label` + a single form control + `HelperText`, and is
the highest-value accessibility component in this wave: it clones its child control to inject
`id`, `aria-describedby`, `aria-invalid`, and `required` automatically, so a caller never has to
hand-wire ids between a label, control, and helper text. Use it whenever building a real labeled
field rather than composing `Label`/`Input`/`HelperText` manually.

```tsx
import { FormField } from 'dial-react';
```

`required` and `invalid` are independent booleans and commonly appear together — a required field
that currently fails validation, such as a password the user hasn't fixed yet, shows both the
required indicator and the error-toned helper text at once.

<Demo code={`<FormField label="Password" required invalid helperText="Password must be at least 8 characters.">
  <Input type="password" defaultValue="abc" />
</FormField>`}>
  <RequiredInvalidFormField />
</Demo>

FormField's id/`aria-describedby` wiring also works with the Collection family, not just native
inputs. `Listbox` renders `role="listbox"` rather than a labelable native element, so FormField
additionally clones in `aria-labelledby` pointing at its own label id — without that, a listbox
nested in a plain `<div>`+`<label>` pairing would have no accessible name at all.

    <Listbox.Item key="jp">Japan</Listbox.Item>
    <Listbox.Item key="us">United States</Listbox.Item>
  </Listbox>
</FormField>`}>

## Accessibility

**Keyboard:** No independent keyboard behavior — delegates entirely to its composed control.

**Screen reader:** This is the component's core job. The cloned control receives `id={fieldId}`
so `Label`'s `htmlFor` resolves without manual wiring; it receives `aria-describedby={helperId}`
whenever `helperText` is supplied, so assistive tech announces the helper/error copy right after
the field's name/value (the single most commonly-missed a11y wire-up in hand-built forms); it
receives `aria-invalid="true"` and `required` mirrored from FormField's own props instead of
needing to be set redundantly on both.

**Focus:** Focus behavior belongs to the composed control; FormField's root `div` is not itself a
focus target. The root exposes a ref via `forwardRef<ElementRef<'div'>>` for callers that need to
measure/scroll to the field.

## Related

- `Label` and `HelperText` — the two atoms FormField composes automatically.
- `Input` / `Textarea` — the most common controls passed as FormField's child.
- `Checkbox` / `Radio` / `Switch` — can also be passed as FormField's child, though inline
  labeling via their own wrapping `label` is more common for single controls.
