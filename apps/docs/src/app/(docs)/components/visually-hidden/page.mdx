# VisuallyHidden

VisuallyHidden is an independent utility that renders content invisible on screen but still
exposed to assistive technology.

```tsx
import { VisuallyHidden } from 'dial-react';
```

## Demo

<Demo code={`<button aria-label="Close">
  <span aria-hidden="true">×</span>
  <VisuallyHidden>Close</VisuallyHidden>
</button>`}>
  <BasicVisuallyHidden />
</Demo>

## Usage

VisuallyHidden is an independent utility (D-012, no props beyond `children`) that renders content
invisible on screen but still exposed to assistive technology, using the standard CSS "clip"
pattern rather than `display: none`. Use it to give screen-reader-only text to otherwise
visual-only controls — most commonly labeling icon-only buttons.

## Variants

VisuallyHidden has no variants — it is an independent utility with no props beyond `children` and
standard `span` DOM props.

## Composition

Its most common consumer is `IconButton`: the `aria-label` prop already gives the button an
accessible name, but some teams prefer real text content over an attribute for the same reason
Spinner does — VisuallyHidden here gives the delete control that redundant, always-real-text name
alongside the icon glyph, which stays `aria-hidden`-equivalent via the icon's own decorative markup.

<Demo code={`<IconButton aria-label="Delete item" variant="ghost" intent="danger">
  <VisuallyHidden>Delete item</VisuallyHidden>
  <TrashSvg />
</IconButton>`}>
  <VisuallyHiddenIconButtonLabel />
</Demo>

A second common use is a skip link: the link text needs to exist for screen reader and keyboard
users to jump past repeated navigation, but most sighted users never need to see it, so the label
is wrapped in VisuallyHidden rather than styled small or given `opacity: 0` (which would strip it
from the accessibility tree along with the visual).

<Demo code={`<Link href="#main-content" variant="default">
  <VisuallyHidden>Skip to main content</VisuallyHidden>
</Link>`}>
  <VisuallyHiddenSkipLink />
</Demo>

## Keyboard interaction

No keyboard behavior beyond native Tab focus — VisuallyHidden is non-interactive and does not
manage focus or add any keyboard behavior itself.

## Accessibility

**Keyboard:** N/A — non-interactive; it does not manage focus or add any keyboard behavior itself.

**Screen reader:** Content remains in the accessibility tree and is announced normally by screen
readers — it's visually clipped via CSS, not removed via `display: none`, which is tested
explicitly (`getComputedStyle(el).display` is asserted not to be `'none'`).

**Focus:** Not inherently focusable; renders a plain `span`. If wrapping focusable content, that
content's native focus behavior is unaffected.
