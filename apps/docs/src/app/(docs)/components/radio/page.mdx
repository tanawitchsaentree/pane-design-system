# Radio

Radio renders a native `<input type="radio">`, visually hidden underneath a custom ring-and-dot
indicator. Like Checkbox, it deliberately skips React Aria/Radix roving-tabindex code — the
browser already roves focus between same-`name` radios for free. Use it for single-choice
selection within a named group, typically composed inside `Fieldset` for group semantics.

```tsx
import { Radio } from 'dial-react';
```

## Accessibility

**Keyboard:** Tab moves focus onto/off the radio group (verified in `Radio.test.tsx`). Arrow-key
roving focus (ArrowUp/Down/Left/Right moving selection between same-`name` radios) is native
browser behavior, not code this component implements. The source explicitly documents that jsdom
— used by the Vitest suite — does not fully implement native radio-group arrow-key roving focus,
so **this is not covered by an automated test**; it must be manually verified in a real browser
session before relying on it. Treat it as expected-to-work-natively, not "tested."

**Screen reader:** The native input carries the real `checked`/`disabled` state and receives
focus, so screen readers announce role/state exactly as a normal radio button. The custom ring is
`aria-hidden` and purely decorative.

**Focus:** Focus-visible renders as an outline ring around the custom ring element, not a shadow.
The wrapper (`label`) has a 40px `min-inline-size`/`min-block-size` hit area (`size.control.sm`)
while the visible ring stays visually smaller (`size.icon.lg`) and centered via flex — same
pattern as Checkbox/Switch.
