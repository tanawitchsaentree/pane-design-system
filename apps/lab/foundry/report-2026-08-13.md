re-derived); (2) forced-colors non-shadow-only state cue (every raised→pressed transition keeps its
existing fill/border shift alongside the new shadow, per D-029's own guardrail — checked by reading
each component's own state CSS, not assumed); (3) D-001 accent-scarcity (no niche adds a second
accent color — confirmed, all three niches reuse the exact same `action.primary`/`brand.*` tokens,
only depth/radius vary).

## Novelty pressure

Checked pairwise per component: does niche B read as visually distinct from A, and C from B?

- **Button/Switch/Checkbox/Input (control/input classes):** A vs B vs C are genuinely distinct —
  A has zero shadow at any state, B has a light, single-direction shadow that swaps direction on
  press, C has a visibly heavier version of the same swap plus a thicker border. All three survive
  novelty pressure as real, different positions.
- **Card (surface class):** A vs B are visually IDENTICAL (B's "faithful" niche for this class
  reduces to "unchanged," since FORM.md's surface-class rule is explicitly no-depth) — this is a
  real novelty-pressure collapse, reported rather than hidden. Effective K for Card is **2**, not
  3: {A/B collapsed-to-one, C (thicker border)}.

## Fill-rate (honest, per the skill's own report template)

- Button, Input, Switch, Checkbox: fill-rate = 3/3 = 100%, all three niches distinct.
- Card: fill-rate = 2/3 effective (A and B collapsed to one candidate under novelty pressure,
  reported as a real finding about this component's class, not a generation failure) = **67%**.

## Judging (separated from generation — judged against system/FORM.md's class table + the measured
reference image directly, not against the generation reasoning above)

- **Button, Switch, Checkbox, Input:** Niche B (FORM.md-faithful) is the judge's pick. Reasoning:
  the measured reference itself shows a SUBTLE cast shadow (15-25% darkening, not a strong 3D
  render) — niche C's heavier depth step and thicker border overshoots what the actual reference
  image supports, reading as a more generic "neumorphic app" language than what the specific Braun
  illustration set shows. Niche A remains the honest "no change" baseline, correctly rejected
  because it's the exact generic-attractor problem (`form-language/references/evasion-form.md`)
  this whole order exists to fix.
- **Card:** Niche C (thicker `border.interactive`) is the judge's pick over the collapsed A/B, on
  the basis that the reference's device bodies do show a crisper, more defined edge than Dial's
  current thin hairline-derived border — a real, small, class-appropriate adjustment consistent
  with FORM.md's explicit "surface stays flat, no depth token" rule while still responding to the
  reference's own crisper edge.
